# Architecture Decision Records (ADRs)

What belongs here:
- One short Markdown file per significant technical decision, e.g.
  `0001-use-postgresql.md`, `0002-jwt-over-sessions.md`.
- Each ADR should cover: the decision, the context/problem, the
  alternatives considered, and why this option was chosen.
- This is a professional practice that gives future-you (or a new
  contributor) the "why" behind a choice, not just the "what" - especially
  valuable in a learning project where the learning is the point.

Suggested template per file:
    # Title
    ## Status (proposed / accepted / superseded)
    ## Context
    ## Decision
    ## Consequences
